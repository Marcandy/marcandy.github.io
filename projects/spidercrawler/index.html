spiderCrawler

A Python pipeline that monitors Pennsylvania criminal rulemaking, verifies extracted claims against source text, and routes every item to human review.

  • Python
  • PDF extraction
  • LLM APIs
  • Human review
  • GitHub Actions
Repository ↗

Problem

Rulemaking updates arrive as committee-page entries and PDFs. A useful change monitor must preserve the source of each claim and prevent unsupported summaries from reaching a published digest.

Approach

The Python pipeline fetches committee pages, checks their structure, detects new items, extracts PDF text, and requests structured summaries. A deterministic verifier checks source quotations, dates, and rule identifiers before routing records to a local review app.

Key decisions

  • Keep the model inside a checked pipeline. Fetching, detection, source checks, routing, and publication remain deterministic steps around extraction.
  • Fail closed on unsupported claims. Blocked records cannot be approved; edited summaries pass through verification again.
  • Require human approval. The digest includes only approved items with source and review provenance.
  • Detect source changes. Unexpected page structure or record counts stop processing rather than silently producing misleading updates.

Result and limits

The repository documents an implemented pipeline, verifier, review app, digest, evaluation harness, and offline test suite. As of November 1, 2026, evaluation results and external reviewer validation are still pending. These are implementation claims, not measured extraction accuracy.

This is a rulemaking-monitoring project, not legal advice. Read the limitations and evaluation plan with the source.

Next validation
