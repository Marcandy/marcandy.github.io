Vera

A full-stack home care beta that connects visits, caregiver documents, evidence review, and billing readiness with server-enforced access rules.

  • React
  • Vite
  • React Router
  • CSS Modules
  • Java
  • Spring Boot
  • MySQL
Live demo ↗ Earlier frontend source ↗

Problem

Interviews with home care agency owners in Philadelphia highlighted disconnected caregiver paperwork, visit tracking, and patient signatures. Vera connects these tasks in one workspace, from a scheduled visit to evidence review and billing readiness.

My role

Designer and developer, from agency-owner interviews and interface design to the React client and Java Spring Boot API.

Approach

Administrators manage patients, caregivers, document review, visits, and billing. Caregivers use a phone-width interface for their assigned visits, check-in, checkout, and document submissions. React services call the API; Java services enforce the rules over MySQL records.

Key decisions

  • Enforce access on the server. Sessions, roles, and ownership checks constrain access to caregiver records and visit actions.
  • Keep domain transitions in services. Check-in, checkout, missing evidence, and simulated claim submission have explicit service operations.
  • Require evidence to resolve flags. Missing assessment or signature evidence must be supplied before a visit becomes billable.
  • Preserve document history. Pending renewals do not replace accepted credentials until review; private downloads and document policies remain server-controlled.

Result and scope

The live beta at veraforcare.com connects the React interface to the Spring Boot API and persistent MySQL data. The full-stack repository is private. The earlier frontend repository is available separately and does not represent the current backend.

Vera is an EVV-inspired beta using fictional demo data and simulated claim submission. It is not certified EVV software and makes no HIPAA claims. The screenshot above records the earlier frontend interface.

Next validation

Continue checking role boundaries, visit transitions, and document renewal behavior as the beta grows. Separate demonstrated product behavior from certification or operational outcomes that have not been established.
